# CryoSat

NeoForge 1.21.1 addon for Mekanism 10.7 (cryogenics plus orbital/space content). Parchment mappings
on top of Mojang names. Java 21. Package `io.github.valajar.cryosat`, mod id `cryosat`.

## Build and verify

* `./gradlew build` must pass before committing.
* There is no game client in cloud sessions. Verify behaviour with game tests:
  `./gradlew runGameTestServer` runs every `@GameTestHolder` class in
  `io.github.valajar.cryosat.gametest` headless and exits (non zero on failure). Tests use the
  1x1x1 `cryosat:empty` structure unless they need a real arena. `runServer` does not receive
  stdin through Gradle, so it never stops on its own.
* Mekanism is a `compileOnly` dependency on its `api` classifier. Only use `mekanism.api.*`
  unless there is no API for something; if you must reach into Mekanism internals, switch that
  dependency deliberately and say why in the commit.

## Conventions

* Registries live in `io.github.valajar.cryosat.registries`, one class per registry
  (`CryoChemicals`, later `CryoBlocks`, `CryoItems`, ...), each exposing a `DeferredRegister`
  registered from the `CryoSat` constructor.
* Chemicals go into Mekanism's chemical registry (`MekanismAPI.CHEMICAL_REGISTRY_NAME`) so they
  work with Mekanism tubes and tanks.
* Lang keys: chemicals use `chemical.cryosat.<name>`.
* Prefer data generation for models, blockstates, loot tables, recipes and tags once a datagen
  setup exists; hand written JSON only for Blockbench models.

## Textures and models

Read `docs/texture-style-guide.md` before touching any PNG or model JSON. Textures are generated by
deterministic Python scripts in `tools/textures/gen/` using `tools/textures/texlib.py` and the
palette in `tools/textures/palette.py`. Always render a preview with `tools/textures/preview.py`
next to Mekanism references and look at it before committing.
